## Independent test of the stage controller

The `run_native_serialized` helper was extracted from `native/tests/conformance.py`. The local copy matched the GitHub-sourced helper's **1,440-character length** and **FNV-1a 32-bit fingerprint 2248846160**. This non-cryptographic fingerprint is an accuracy check for the local transfer, not a signature or authentication.

The committed mock-stage test file `tests/test_native_conformance_driver.py` matched Git blob SHA-1 `cd98d4f6b39240f5545e7db62d473db820f34559` against the locally tested version.

**Environment:** Python 3.13.5, pytest 9.0.2, Linux, disposable local CLI simulator. No network, no hosted runner, and no GitHub Actions.

```sh
python -m pytest -q tests/test_native_conformance_driver.py
```

Observed result in a focused reconstructed checkout:

```text
....                                                                     [100%]

```

The four tests cover:
- Successful `compile` → `check-bytecode` → `run-bytecode`, including forwarded standard input.
- Failed compile must not start validation or execution.
- Failed bytecode validation must not start execution.
- A runtime error must remain visible as a nonzero result and captured diagnostic.

**Limitation:** The CLI simulator is **not Kasa**. These tests check only subprocess sequence/error handling. The focused local checkout did **not** contain the full Python runtime or full native compiler/VM, so no reference-versus-native output claim is justified. The mock executable uses a POSIX shebang; the test module explicitly skips on Windows.

## Remaining acceptance gate

From a **complete** repository checkout, compile the native Kasa executable and run:

```sh
python -m pip install -e ".[dev]"
python scripts/verify_local.py --profile full
# Full profile includes:
python native/tests/conformance.py build/kasa-local/kasa-native
```

Record the exact branch/commit, environment, full JSON output and any failing fixture. Only mark the **58 real parity cases** as passed after observing successful native execution. On Windows, use the executable path generated by the platform's CMake configuration.

**Risk:** The test corpus can uncover deliberate native 64-bit integer limits, formatting discrepancies, runtime error-category differences, or actual semantic bugs. Investigate these independently rather than changing expected outputs to suit one engine.

**Review decision:** PR #22 remains open until this native/Python compatibility gate is executed; the completed 4/4 simulated-CLI tests do not waive it.
